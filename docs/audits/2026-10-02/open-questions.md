# 결정 사항과 미확인 영역

전체 계획 작성은 완료하되 다음 정책은 구현 전에 확정한다. 답을 기다리는 동안 안전성·현재 동작 검증·공개 UI 개선 설계는 진행할 수 있다.

| 결정 | 현재 근거 | 권장안 | 영향 |
|---|---|---|---|
| 첫 출시 범위 | 전체 계획에 따른 개발 시작 승인 | 학생 집중 안정화 → 보호자 → 테스트 결제 → live 단계 출시 | 승인된 단계 개발 순서이며 요구 삭제 아님 |
| deposit 성공 기준 | v3 all-or-none; 현재 목표 개수별 0/60/80/100 전환 | v3를 기준으로 확정하되 기존 세션은 생성 당시 정책 보존 | policy version 또는 고정 snapshot, 과거 거래 재정산 금지 |
| guardian 보상 승인 시점 | v3 시작 전 승인; 현재 세션 생성 후 요청/승인 | 시작 전 요청·승인·예약, 미승인시 guardian 지원 없는 시작을 명시 선택 | plan/ready/start 데이터 계약 변경 |
| 보호자 학생 수·과금 | v3 여러 학생; 현재 문서·상품에 포함수/추가좌석 정책 | 기존 상품을 임의 제거하지 않고 명시된 제한과 가격을 한 설정으로 정합화 | 계약·UI·entitlement·migration |
| 실결제·환불·현금화 | 현재 테스트만, 환불/지급 sandbox | provider 취소·대조 테스트 완료 후 live gate; 자동 현금화는 계약 전 off | 외부 계약 기간은 개발 추정 제외 |
| Widget 요구 | 현재 SDK payment request 사용 | v3 Widget 목표를 채택하면 공식 Widget 통합; 현재 SDK 경로의 테스트는 보존 | 결제 UI 변경 범위 |
| 모바일 집중 | PWA만으로 Chrome 데스크톱 Extension 차단을 제공할 수 없음 | 모바일은 계획·기록·가족·지갑, 차단 집중은 지원 브라우저 안내 | 설치·온보딩·시작 화면 |

## 검증 질문

1. 배포 DB의 최종 함수 정의·grant·migration은 저장소와 일치하는가? 로컬 DB fixture로 E01을 먼저 재현하고 staging에서 비교한다.
2. 승인/종료 RPC lock 순서 차이가 실제 deadlock 또는 중복 정산을 만드는가? 두 connection에서 barrier를 두고 검증한다.
3. 무료/유료 학생·보호자, 다른 사용자, 연결 해제 계정의 RLS·AI scope는 예상대로인가?
4. 같은 브라우저의 Web/Extension 로그인 계정이 다르면 시작·예약·복구는 어떻게 끝나는가?
5. 브라우저/SW 종료·로그아웃·오프라인을 거쳐 DNR 해제와 정산이 한 번만 이루어지는가?
6. Toss 승인/취소 성공 직후 DB 실패, callback 중복, 금액 변경 후 재시도 시 대조 복구가 가능한가?
7. 개인정보 안내는 자동 수집/로컬 처리/사용자가 요청한 전송/보호자 공유를 각각 설명하는가?
8. 실제 지원 브라우저·기기에서 설치, SW 업데이트, 알림 거부/철회, 만료 구독 정리가 동작하는가?
9. 세션 보존 기간과 ledger 참조·환불/분쟁 증거의 보존 정책은 일치하는가? 금융 연결 세션을 일반 sync cleanup이 제거해도 되는지 검토한다.
10. 실제 CI·에러 관측·복구 절차가 외부 서비스에 존재하는가? 저장소에서 찾지 못한 것을 운영에서도 없다고 단정하지 않는다.

현재 OAuth·결제·연결·운영 DB mutation은 실행하지 않았다. 위 미확인을 ‘문제 없음’으로 처리하지 않는다.

## 1차 개발 후 상태

범용 canonical sync 변조는 로컬 SQL과 두 연결 경합에서 재현·차단했다. 공유 철회·연결 해제 권한 및 집중 시작 확인은 로컬 회귀를 통과했다. deposit 비율과 guardian 승인 시점은 이번 변경에서 유지하며 W06/W08에서 기존 거래 호환성을 포함해 변경한다. 운영 DB, 실제 OAuth·Chrome·provider 검증은 남아 있다. 자세한 범위는 [진행 기록](../../superpowers/plans/2026-10-02-project-completion-progress.md)을 따른다.

2차에서 canonical sync 보호와 privacy RPC를 원격 적용하고 lint 및 익명 요청 거부를 확인했다. Chrome 실제 로컬 차단·재시작 smoke 8개를 통과했다. OAuth 실계정·Web canonical 세션·운영 provider는 여전히 미확인이다. [2차 기록](../../superpowers/plans/2026-10-02-project-completion-phase-2.md)을 함께 본다.
