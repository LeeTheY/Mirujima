# 보호자 연결 UI 및 코드 발급 복구 설계

## 목표

보호자 연결 코드 발급 위치를 보호자 마이페이지로 일원화하고, 보호자 마이페이지를 학생 마이페이지와 같은 3열 × 2행 카드 체계로 정리한다. 동시에 연결 코드 발급 실패의 서버 경계를 추적해 원인을 제거하고, 학생의 6자리 코드 입력 경험을 복원한다.

## 화면 책임

- `/guardian`: 연결 상태 요약과 `/guardian/my`로 이동하는 `연결 코드 입력하기` CTA만 제공한다.
- `/guardian/students`: 연결된 학생 목록과 보상 요청만 제공하며 코드 발급 UI와 발급 안내 문구를 제거한다.
- `/guardian/my`: 보호자 계정, 멤버십, 지갑, 학생 연결 코드 발급/연결 목록, 가족 활동, 보상 요청의 6개 카드를 제공한다.
- `/my`: 학생만 보호자가 발급한 6자리 코드를 입력한다.

## 보호자 마이페이지 디자인

학생 마이페이지의 `settings-grid`, `card`, `sub-card`, badge, 버튼 구조를 그대로 사용한다. 데스크톱에서 모든 카드는 같은 grid span을 사용해 3열 × 2행을 유지하고, 태블릿과 모바일에서는 기존 반응형 규칙에 따라 축소한다.

역할별 콘텐츠는 다음과 같다.

1. 로그인 계정 정보: Google 인증 상태, `profiles.display_name`, 보호자 권한
2. 멤버십 서비스: 현재 상태, 혜택 안내, 결제 정보 링크
3. 보호자 지갑: 충전/예약/지급 가능 포인트 요약과 충전 링크
4. 연결 학생: 연결 코드 발급, 남은 시간, 연결된 학생의 `display_name`
5. 가족 활동 요약: 학생이 동의한 집계 정보만 표시하고 기록 페이지로 이동
6. 보상 요청 관리: 대기 요청 상태와 학생 페이지로 이동

## 연결 코드 입력 디자인

실제 입력은 접근 가능한 단일 숫자 input을 유지한다. 화면에는 6개 칸을 렌더링해 값이 없는 칸에 `0`을 표시하고, 포커스/입력 상태를 시각적으로 구분한다. 접힌 버튼의 우측 아이콘은 아래쪽 화살표로 바꾼다.

## 코드 발급 장애 조사

클라이언트 → Supabase Edge Function → 인증 → origin allowlist → signing secret → RPC의 순서로 경계를 확인한다. 원격 secret 이름과 함수 배포 상태를 읽기 전용으로 확인하고, 서버가 반환한 안전한 오류 코드를 클라이언트가 안정적으로 표시하도록 한다.

필수 서버 설정은 다음과 같다.

- `MIRUJIMA_ALLOWED_ORIGINS`: 로컬 및 배포 origin의 쉼표 구분 목록
- `MIRUJIMA_SERVER_SIGNING_SECRET`: 24자 이상의 코드 HMAC secret
- Supabase 기본 제공 URL, publishable/anon, service-role/secret 키

원인이 설정 누락이면 필요한 secret을 추가하고 관련 Edge Function을 재배포한다. 원인이 코드 결함이면 실패 테스트를 먼저 작성한 뒤 최소 수정한다.

## 회귀 방지

- 보호자 학생 페이지에는 issuer가 없어야 한다.
- 보호자 홈 CTA는 `/guardian/my`로 이동해야 한다.
- 학생 코드 입력은 기본 접힘 상태이며 펼치기 아이콘은 아래 방향이어야 한다.
- 보호자 마이페이지에는 정확히 6개의 동일 span 카드가 있어야 한다.
- 코드 발급 오류는 raw 서버 메시지나 secret을 노출하지 않는다.
