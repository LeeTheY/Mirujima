# 인증 세션 및 온보딩 화면 정비 설계

## 목표

- 대시보드의 로그아웃을 누르면 Supabase 인증 세션과 브라우저 쿠키가 종료되고 온보딩으로 이동한다.
- 로그아웃 후 Google 로그인을 다시 누르면 새 OAuth 로그인을 시작할 수 있다.
- 온보딩은 비로그인 상태와 로그인 완료·역할 미선택 상태를 분리해, 서로 맞지 않는 문구와 CTA를 표시하지 않는다.
- 온보딩 레이아웃은 프로젝트 자체 CSS에 의해 데스크톱과 모바일에서 일관되게 표시된다.

## 현재 상태와 문제

- `signOut`은 서버에서 `supabase.auth.signOut()`을 호출하지만 실패 처리가 없고 루트로 이동한다. 로그아웃 완료 후의 명확한 진입점은 온보딩이다.
- 온보딩은 이미 역할 선택 분기를 갖고 있지만, 비로그인용 Google 인증 패널과 Tailwind 유틸리티에 의존한 여백·정렬이 섞여 있다. 프로젝트의 전역 CSS는 Tailwind를 보장하지 않으므로 화면 밀도와 배치가 불안정하다.

## 설계

### 1. 로그아웃

- `signOut` 서버 액션에서 Supabase 전역 로그아웃을 호출한다.
- Supabase 오류가 있으면 액션을 실패시켜, 세션이 남은 채로 화면만 바뀌는 상태를 만들지 않는다.
- 성공하면 `/onboarding`으로 리다이렉트한다. 다음 요청에서 Proxy와 서버 컴포넌트가 만료된 인증 쿠키를 읽어 비로그인 상태를 렌더링한다.
- 대시보드의 기존 form action 구조는 유지한다.

### 2. 온보딩 상태별 콘텐츠

| 상태 | 좌측 설명 | 우측 CTA |
| --- | --- | --- |
| 비로그인 | Google 계정으로 웹·확장 기록을 연결한다는 제품 소개와 개인정보 원칙 | Google 로그인 카드 |
| 로그인 완료·역할 미선택 | “어떤 방식으로 시작할까요?”와 역할이 홈 화면을 결정한다는 안내 | 학생/보호자 역할 선택 카드 |
| 로그인 완료·역할 선택 완료 | 기존 역할별 홈으로 서버 리다이렉트 | 렌더링하지 않음 |

- 로그인 완료 상태에서는 `Google Authentication`, `Mirujima 계정 로그인`, 보안 로그인 및 둘러보기 링크를 렌더링하지 않는다.
- 역할 선택 영역의 제목은 `집중 학습으로 가기`로 표시한다. 버튼은 학생/보호자 역할을 설정한 뒤 각 홈으로 이동한다.

### 3. 레이아웃

- `onboarding-action-wrap`을 명시적인 폭과 수직 정렬 컨테이너로 정의한다.
- 로그인 카드 내부의 정렬·여백·구분선·텍스트를 전용 클래스에 옮긴다. Tailwind 유틸리티 클래스에 화면 구조를 의존하지 않는다.
- 900px 이하에서는 좌우 1열, 640px 이하에서는 헤더·카드 패딩과 역할 카드 여백을 축소한다.
- 기존 브랜드 색상, 카드 radius, 네이비 hero와 흰색 action card 체계를 유지한다.

## 오류 처리와 회귀 방지

- 로그아웃 API 오류는 무시하지 않아야 한다. 세션 종료가 확인되기 전에는 리다이렉트하지 않는다.
- Supabase 공개 설정이 없는 로컬 미리보기는 기존 학생 화면 미리보기 동작을 유지한다.
- 이미 역할이 설정된 사용자는 계속 기존 홈으로 자동 이동한다.

## 검증

1. 인증된 학생/보호자가 로그아웃하면 `/onboarding`에 비로그인 화면이 표시되는지 확인한다.
2. 로그아웃 후 Google 로그인 CTA가 다시 표시되고 OAuth 요청을 시작하는지 확인한다.
3. 역할이 없는 인증 사용자는 Google 로그인 문구 없이 `집중 학습으로 가기` 및 역할 카드만 보는지 확인한다.
4. 기존 역할 라우팅과 auth action 단위 테스트를 실행하고, 추가한 로그아웃·온보딩 상태 테스트를 통과시킨다.
5. 데스크톱과 900px/640px 화면폭에서 온보딩 카드가 겹치거나 넘치지 않는지 확인한다.
