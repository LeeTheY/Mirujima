# Mirujima 프로젝트 완성 설계안

상태: 사용자 검토용 전체 설계. 작성일 2026-10-02. 제품 구현·배포 승인을 뜻하지 않는다.

## 목표

학생이 계획을 만들고 실제 차단 집중을 수행한 뒤 기록과 포인트 결과를 믿을 수 있게 확인하며, 보호자가 학생의 동의 범위 안에서 지원하는 흐름을 완성한다. ‘완벽’은 모든 기능 수를 늘리는 대신 **허위 성공 없음, 권한 우회 없음, 상태 복구 가능, 실제 데이터 표시, 주요 과업의 접근성**이라는 완료 조건으로 바꾼다.

## 접근법 비교

| 접근 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 권장: 현재 구조에서 학생 핵심 흐름부터 단계별 완성 | 기존 코드·테스트 보존, 위험부터 제거, 단계별 출시 가능 | 초기에는 화려한 새 기능보다 결함 수정이 많음 | 채택 제안 |
| 가장 단순: 미완성 버튼 숨김·테스트 한정으로 소규모 데모 | 빠르게 오해를 줄임 | 저장/해제/상태 권한 문제 해결을 대체하지 못하며 전체 요구 미충족 | 긴급 임시 조치에만 사용 |
| 유지보수·확장: 공유 도메인·공통 UI·관측을 먼저 전면 정리 | 장기 일관성 확보 | 검증 안 된 기능 위에 재구조화 비용과 회귀 증가 | 안정화 후 변경이 잦은 경계부터 점진 적용 |

## 사용자 흐름

**학생:** 로그인 → 역할 → 확장 설치/계정 상태 확인 → 계획 초안/저장 → guardian 지원 요청 및 승인 확인 → 금액·차단 설정 최종 확인 → 시작 준비 → 집중/휴식 → 결과 동기화 → 기록·정산 확인.

**보호자:** 로그인 → 역할 → 코드 발급/입력 → 학생 공유 범위 확인 → 보상 요청 검토 → 예약 → 결과별 지급/반환 → 기록 확인 → 미정산 검사 후 연결 해제.

**실패 복구:** 서버/Extension/provider 상태를 확인 중인 경우 ‘완료’ 대신 ‘확인 중’을 표시한다. 다시 시도할 때 같은 요청의 결과를 찾고 불필요한 새 세션·주문을 만들지 않는다. 오류를 0P·미연결·기록 없음으로 표시하지 않는다.

## UX 설계

- 기존 Mirujima 네이비 hero, cobalt action, 밝은 배경과 Pretendard를 유지한다. desktop 본문 최대 폭 1120~1200px, mobile 1열 원칙을 적용한다.
- 모바일 header는 제품명과 주 행동을 읽을 수 있게 유지하고 보조 링크는 별도 행/메뉴로 옮긴다. 단계 설명은 mobile 1열, tablet부터 여유에 맞춰 2~3열로 바꾼다.
- how/privacy에 공통 container·header·grid를 연결한다. login은 모바일 첫 화면에서 로그인 행동을 찾을 수 있게 메시지를 압축하고 Supabase user ID 같은 내부 설명을 뺀다.
- 로그인 필요 CTA는 결과를 미리 알려준다. 설치 불가 환경에서는 ‘확장 실행’만 반복하지 않고 가능한 과업과 데스크톱 연결 경로를 제공한다.
- 학생/보호자 모든 카드에 loading, empty, error, ready 상태를 정의한다. 성공 문구는 서버 응답 이후 표시한다.
- PaymentOverlay의 keyboard/focus 패턴을 기존 모달에 일관되게 적용한다. 공통 모달 도입 시 결제 뒤로가기·intercept route 동작을 회귀 확인한다.
- 재무 영역은 topup/reserved/earned와 충전 환불/획득 지급을 구별한다. 테스트 환경임을 결제 직전뿐 아니라 관련 잔액·활동 화면에도 알린다.
- 차트는 질문이 있는 지표에만 사용하고 데이터 표와 동일한 집계를 제공한다. 빠진 요구를 채우기 위해 의미 없는 5종 차트를 늘리지 않는다.

## 기능 경계와 데이터

[구조 문서](../../audits/2026-10-02/architecture.md)의 서버 권한과 상태 전이를 따른다. `profiles.sharing_preferences`, `family_links`, 기존 cloud payload, wallet ledger, notifications를 우선 사용한다. 기존 원장·완료 세션의 의미를 새 정책으로 소급 변경하지 않는다.

공유 설정은 DB 계약의 `shareCompletion`, `shareTotalFocusMinutes`, `shareRewardStatus`, `shareAiSummary`를 사용한다. 기본값은 true/true/true/false다. 저장·철회는 보호자 RPC와 AI 최소 데이터 구성에 반영된다.

Extension 직접 응답과 resync가 같은 세션을 다루게 한다. 적용 확인은 세션 식별·계정 일치·DNR 실패 감지를 위한 것이며 악성 사용자의 브라우저까지 신뢰 가능하게 만든다는 보장은 아니다.

## 출시 완료 조건

1. P0 권한·공유·실제 상태 변경 문제에 재현 및 회귀 증거가 있다.
2. 학생 시작→휴식→종료→기록, 보호자 연결→승인→정산→해제 경로가 테스트 계정으로 완주된다.
3. 인증 E2E와 DB/RLS 검증이 누락되면 release gate가 실패한다.
4. 브라우저 종료·오프라인·중복 요청·provider 성공 후 DB 실패에도 결과가 대조·복구된다.
5. 목표 viewport에서 주요 과업이 가능하며 공개·인증 화면의 핵심 UI 평가 각 항목이 8/10 이상이다. 점수와 별개로 키보드·표준 접근성 검사 결함을 해결한다.
6. live 결제·자동 지급은 계약·환불정책·미성년자·법률/회계 등 v3 출시 gate 완료 후 별도 전환한다.
