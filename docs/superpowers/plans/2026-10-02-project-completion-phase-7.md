# 7차 개발: 지갑 조회 실패·미확정 거래 표시

승인된 W09 계획의 지갑 조회·충전/환불 표시 경계를 구현했다. 실제 로그인 테스트 계정은 준비되지 않아 인증된 원격 잔액 대조는 미검증이다. W09 전체 완료로 처리하지 않는다.

## 변경과 영향

- 지갑 조회는 `ready`와 `unavailable`로 구분하고 조회 시각과 실패 종류를 보존한다. 실제 0P는 유효하며 오류 응답에 포함된 숫자나 누락·음수·소수·안전 범위를 벗어난 숫자를 잔액으로 사용하지 않는다.
- 홈·학생/보호자 마이페이지에 조회 시각, 예약 포인트와 충전 환불/획득 지급의 차이, 서버 재조회 버튼을 추가했다. 현재 지급 계약 확인 전 실제 송금이 활성화되어 있다고 안내하지 않는다.
- 환불·현금화 모달은 잔액 조회 실패 시 0P 폼을 만들지 않는다. 환불 한도가 없거나 유효하지 않으면 환불 신청도 차단한다. 재조회로 갱신된 서버 값은 새 폼으로 반영된다.
- 환불 결과 형식·금액·잔액·환불 한도를 확인하지 못하면 후속 신청을 중지하고 재조회를 안내한다. 중복 클릭은 실행 중 ref로 막으며 성공을 확인하기 전 잔액을 변경하지 않는다. 실제 환불이 서버에서 완료되었는데 응답이 유실된 경우도 있어 ‘잔액은 변경되지 않았다’고 단정하지 않는다.
- 충전 내역은 조회 실패와 실제 빈 목록을 구분하고 재조회 버튼과 확인 시각을 표시한다. 최근 원장 100건에서 미확정 주문·환불 예약·실패·완료를 구분하며 연결된 완료 거래가 있으면 이전 요청 항목을 숨긴다. 페이지 전체 거래 이력이나 확정 잔액 계산에 이 제한 목록을 사용하지 않는다.
- 거래 응답의 종류·상태·금액·날짜·사용자 소유권을 확인한다. 주문/연결 거래 ID만 표시하며 provider payment key, raw metadata, 원문 오류를 조회하거나 표시하지 않는다. 구체적인 제공자 실패 사유는 아직 조회하지 않으며 확인 필요 안내를 표시한다.
- 내역 모달은 기존 Dialog의 focus 복원·Tab 이동·Escape 닫기를 사용한다. 모바일 중복 내부 여백을 제거했다.
- 충전 성공 응답에 잔액이 없으면 충전 완료와 잔액 확인 불가를 분리한다. 금액/상태가 맞지 않으면 완료로 표시하지 않는다. 지연·알 수 없는 승인 실패도 잔액 불변을 단정하지 않는다.
- `wallet-summary` Edge Function의 환불 한도 RPC 실패/누락을 0P로 반환하던 동작을 제거했다. 조회 실패는 안전한 오류 응답이며 인증·원장·RLS 정책은 변경하지 않았다.

테이블·컬럼·원장 계산·정산 정책·Extension 동작을 변경하지 않았다. 거래 내역의 표시 항목이 늘고 조회 실패 시 환불/현금화 폼이 숨겨지는 것이 의도된 동작 변경이다.
