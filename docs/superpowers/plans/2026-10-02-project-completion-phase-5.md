# 5차 개발: 집중 시작 전 보호자 보상 승인

승인된 전체 개발 설계의 W08 중 보상 요청→승인→예약→집중 시작 경계를 구현했다. 기존 `wallet_transactions`를 재사용하며 신규 테이블은 만들지 않았다. 실제 테스트 계정은 아직 없어 로컬 검증부터 진행한다는 사용자 선택을 유지한다.

## 구현

- 학생은 저장한 계획으로 `request_planned_guardian_reward`를 호출한다. 금액과 보호자는 서버가 계획·활성 연결에서 읽으며, 요청 시 서버가 미래 집중 세션 ID를 발급한다. 중복 요청은 같은 결과를 반환하고 5분 동안 신규 요청 5회로 제한한다.
- 보호자는 세션이 생성되기 전에 승인한다. 승인은 기존 불변 원장에 `topup → reserved` 거래 하나를 추가한다. 승인 전 집중 시작은 학생 디파짓 예약·세션 생성 전에 거절한다.
- 승인된 집중 시작은 요청의 미래 세션 ID를 사용한다. 거래의 session_id를 사후 수정하지 않는다. 기존에 시작한 세션과 이전 정산 정책은 유지한다.
- 학생 화면에 요청/승인 확인/취소를 제공한다. 저장하지 않은 변경은 요청 전에 거절한다. 요청 대기·승인 중에는 계획을 잠그고 승인된 저장본으로 시작하므로 disabled FormData 누락이나 승인 후 재저장 오류를 피한다.
- 학생의 시작 전 취소는 승인된 보호자 예약을 한 번만 반환한다. 확장 프로그램 차단 적용 실패·시작 취소는 학생과 보호자의 디파짓을 모두 반환하고 계획을 준비 상태로 복구한다.
- 승인·거절·시작·휴식·종료·시작 취소·연결 해제는 학생 단위 `focus-start` 잠금을 먼저 획득한다. 기존 요청/세션/지갑 잠금을 그 뒤에 사용한다.
- 보호자 승인 응답의 요청 ID·상태·예약 ID를 확인한다. 승인 메시지가 목록 갱신에 의해 사라지던 문제를 수정하고 새로고침을 추가했다. 학생 취소는 보호자 목록에서 거절과 구분한다.
- 모바일 시작 버튼 문구에 따라 집중 카드가 넘치는 문제를 수정했다.
