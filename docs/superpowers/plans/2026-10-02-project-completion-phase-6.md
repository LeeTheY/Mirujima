# 6차 개발: 연결 코드의 시간·동시 처리 경계

승인된 W08 계획에 따라 연결 코드 만료/재발급/취소/입력 잠금과 보상 승인·연결 해제·환불 경합을 보완했다. 사용자가 테스트 계정이 아직 없다고 확인했으므로 실제 Google Auth와 계정 간 전체 여정은 미검증으로 유지한다.

## 변경 이유와 구현

기존 코드 검증은 트랜잭션 시작 시각인 `now()`를 사용했다. 잠금을 기다리다가 코드가 만료되어도 시작 당시 시각으로 허용할 수 있었다. 신규 0008은 잠금과 코드 행 조회 이후 `clock_timestamp()`로 만료·입력 잠금을 판정한다. 발급도 대기가 끝난 실제 생성 시점부터 정확히 300초를 부여하며, 만료 시각·서버 현재 시각을 함께 반환한다.

재발급·취소·입력은 보호자별 `family-issue` 잠금을 공유한다. 입력은 먼저 학생별 `focus-start`와 `family-redeem` 잠금을 획득하고, 보호자를 잠금 없이 찾은 다음 보호자 잠금을 잡고 pending 행을 다시 조회한다. 재발급된 예전 코드, 사용된 코드, 잠금 중 만료된 코드를 재사용할 수 없다. 기존 `profiles` 실패 카운터와 `family_links`만 사용한다. 테이블/컬럼과 금융 정책은 추가하지 않았다.

Service-role 전용 RPC와 JWT 인증 Edge Function의 역할 검증 구조는 유지한다. 보호자 발급·학생 입력, 기본 좌석/최대 좌석 정책, 학생당 활성 보호자 1명 제약과 기존 연결은 그대로 유지한다. 만료/취소/사용된 코드의 hash는 제거된다.

화면에서는 다음을 변경했다.

- 발급 응답을 잃어도 자동 재발급하지 않는다. 재발급 요청 시 이전 코드 표시를 지워 결과가 불확실한 코드를 전달하지 않게 한다.
- 발급·취소·연결 응답을 runtime schema로 확인한다. 형식만 `active`인 응답이나 다른 학생의 결과를 연결 성공으로 표시하지 않는다.
- 서버 시각과 경과 시간을 바탕으로 countdown을 계산하고, 만료된 숫자는 숨긴다. 형식이 잘못된 날짜는 `NaN`이나 임의 5분으로 표시하지 않는다.
- 학생에게 남은 입력 횟수와 잠금 해제 countdown을 표시하고, 잠금 중 입력/제출을 비활성화한다. 성공하면 입력 코드를 지우고 서버 화면을 갱신한다.
- 좌석·멤버십 충돌 안내는 기존 접근 가능한 Dialog를 사용해 초기 focus와 Escape 닫기를 지원한다.
- 보호자 보상 목록은 foreground/online/수동 새로고침과 승인/거절 후 서버 데이터를 갱신한다. 늦게 도착한 이전 조회 결과가 최신 상태를 덮어쓰지 않게 하며, 승인 피드백을 보존한다.
- 연결 해제 안내에 학생의 시작 전 요청 취소 경로를 반영했다.

동시 처리 검증은 각 시나리오마다 별도 DB를 만들고 독립 연결 2개를 사용했다. 첫 거래가 잠금을 보유하는 동안 두 번째 거래가 약 2초 대기한 후 결과를 확인했다. 테스트 후 DB는 삭제했다.

1. 보호자 잠금 대기 중 코드 만료 → 연결 거절.
2. 재발급과 예전 코드 입력 → 예전 코드 거절, 새 코드 보존.
3. 서로 다른 학생의 같은 코드 입력 → 한 명만 연결.
4. 같은 학생의 서로 다른 보호자 코드 입력 → 활성 보호자 한 명 유지.
5. 발급 잠금 대기 → 대기가 끝난 뒤 온전한 5분 부여.
6. 같은 보호자의 서로 다른 pending 코드 동시 입력 → 좌석 수 초과 연결 거절.
7. 보상 승인 후 연결 해제 → 예약 정산 전 해제 거절.
8. 학생 요청 취소·연결 해제 후 늦은 승인 → 승인 거절, 예약 생성 없음.
9. 환불 예약 후 잔액을 초과한 보상 승인 → 승인 거절.
10. 보상 예약 후 잔액을 초과한 환불 요청 → 환불 거절.

금융 경합은 게시된 테스트 원장과 SQL RPC로 검증했다. 실제 Toss 요청이나 현금 이동은 수행하지 않았다. 5차의 종료·늦은 승인 경합 검증도 유지한다.

## 원격 배포

2026-10-02, Supabase `qhueocvatlgaoupokgmc`에 **`202610020008_family_code_transaction_boundary.sql`만 신규 적용**했다. 별도 release workdir에서 dry-run 대상이 0008 하나임을 확인한 후 적용했고, remote migration list 반영과 `db lint --linked --level error`의 오류 없음을 확인했다.

원격 issue/redeem/cancel RPC의 익명 호출은 모두 HTTP 401 / PostgreSQL `42501`로 거절됐다. 인증된 실제 계정의 코드 발급·입력을 검증한 결과는 아니다. 기존 Edge Function이 반환값을 전달하므로 이번 단계에서 Edge Function 자체 배포는 하지 않았다.

0008은 연결 코드 함수 네 개만 교체하며, 0003·0006·0007의 금융 시작/정산 정책을 참조하거나 변경하지 않는다. 이 세 migration은 계속 원격 미적용이다. Vercel 연결·배포 인증이 없는 상태라 Web UI 원격 배포도 미실행이다. 향후 금융 rollout은 원격 최신 version보다 앞선 미적용 migration을 포함하므로, 별도 dry-run에서 0003·0006·0007을 검토한 뒤 적용해야 한다.

## 남은 범위

W08 전체 출시 완료로 표시하지 않는다. 학생/보호자/무관한 사용자 실계정, 실제 JWT-authenticated Edge Function, 원격 코드 공유·좌석 변경·보상/정산 전체 여정과 실제 공유 설정 반영을 확인해야 한다. 이번 UI의 3초 만료/잠금 fixture와 로컬 SQL 검증을 실제 5분 로그인 여정으로 표현하지 않는다. 다음 개발 범위는 W09 지갑 조회·거래 설명·실패/재시도 흐름이다.
