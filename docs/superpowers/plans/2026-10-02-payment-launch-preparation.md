# 결제 출시 직전 준비

요청 범위: Toss API 테스트 모드 유지, 제품 화면에서 테스트 문구 제거, 실제 production 전환 전 검증. 실제 청구·송금과 production 승격은 실행하지 않는다.

1. 결제·멤버십·환불·거래 내역과 관련 CTA를 사용자 문구로 정리한다.
2. 원장 시뮬레이션을 실제 지급 완료로 표시하지 않는다. 계약된 지급 제공자가 없는 현금화는 UI 및 서버 요청을 차단한다.
3. 테스트 키 검증은 유지한다. 사전 점검과 실제 SDK의 키 종류가 일치하는지 검증한다.
4. 충전·멤버십 승인, 금액 변조, 소유권, 중복 승인, 응답 유실 후 조회, 부분 환불과 재조회 회귀 검사를 실행한다.
5. Web/Extension 빌드, 타입, lint, 공개 Secret 검사를 실행한다. 실제 브라우저에서 문구와 준비 중 상태를 확인한다.
6. 원격 적용이 보류된 금융 migration·handler, 제공자 실호출, 키 전환 순서와 출시 게이트를 문서로 고정한다. 검증하지 않은 provider 흐름을 완료로 표시하지 않는다.

이 범위는 사용자가 승인한 전체 개발 계획과 이번 명시적 지시에 따라 진행한다.
