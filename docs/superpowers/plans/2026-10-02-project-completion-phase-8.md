# 8차 개발: 전체 원장 조회·거래 연결

승인된 W09의 남은 전체 거래 목록을 구현했다. 실제 계정이 없어 인증된 원격 ledger 대조는 여전히 미검증이며, 로컬 구현·회귀 결과와 구분한다.

## 구현과 기존 동작

`/wallet/history`는 학생·보호자 공통 인증 화면이다. 마이페이지와 기존 충전/환불 모달에서 열 수 있다. 전체·충전/환불·집중 디파짓·보호자 보상·획득 포인트 지급 필터를 제공한다. 기존 충전 모달과 모든 재무 mutation은 유지한다.

새 조회 RPC `list_wallet_transactions`는 기존 `wallet_transactions`만 사용한다. `auth.uid()`가 금융 거래의 당사자인 행만 반환하고, 다른 사용자의 ID·bucket·metadata·payment key·idempotency key를 반환하지 않는다. 역할이 보호자라는 이유로 학생의 개인 디파짓 원장까지 읽을 수 없다. 관련 결과가 다른 당사자의 전용 행이면 결과 종류만 제공하고 상세 거래 ID는 숨긴다. 클라이언트가 사용자 ID를 지정할 인자가 없다.

기본 20건, 최대 50건으로 조회하며 `created_at DESC, id DESC`의 cursor를 사용한다. 날짜와 UUID가 함께 있어야 하고 단일 거래 조회와 cursor를 함께 사용할 수 없다. 날짜가 같아도 UUID로 다음 페이지를 정확히 나눈다. 프론트엔드는 PostgreSQL 마이크로초를 유지해 밀리초로 잘못 비교하지 않는다. 조회는 새 테이블/컬럼·금융 원장 쓰기·기존 잔액 산식·정산 정책을 추가하거나 변경하지 않는다.

원장의 각 행을 그대로 표시한다. 예약→반환→지급과 요청→결과를 별도로 유지해 금액을 중복 수입으로 보이지 않게 한다. 미확정 주문은 확정 잔액에 반영되지 않는다고 설명하고, posted인 보상 요청·환불/지급 예약도 최종 성공으로 표시하지 않는다. 연결된 posted 결과가 있으면 원래 예약/요청 행에 결과 종류와 본인이 조회할 수 있는 결과 링크를 표시한다. 전체 목록의 금액 합계를 가용 잔액으로 계산하지 않는다.

계획·세션 ID, 주문 ID, 이전 연결 거래·결과 연결 거래를 확인할 수 있다. 학생의 ‘집중 기록 보기’는 기록 목록, 보호자의 ‘보상 요청 관리’는 보상 목록으로 이동한다. ID를 보여주는 것과 특정 계획/세션 상세를 자동 선택하는 기능은 구분한다. `?transaction=<uuid>`는 단일 본인 거래 조회이며 타인/조회 불가능한 거래는 안전한 빈 결과로 처리한다. 잘못된 주소는 RPC 호출 전에 거부한다.

서버는 사유를 allowlist로 투영한다. 학생 취소·집중 시작 미확인·카드 거절·결제창 취소·인증 중단은 안전한 문구로 안내한다. 원문 제공자 오류는 표시하지 않는다. 구체적인 사유가 없으면 없다고 알리고, 실패한 거래는 결과/잔액 재확인을 안내한다.

조회 오류와 빈 결과는 구분한다. 다음 페이지 조회가 실패해도 이전 성공 목록과 cursor를 보존하며 같은 cursor로 다시 요청할 수 있다. 필터/사용자/대상 거래/수동 재조회 시 화면 인스턴스를 새로 만들어 이전 응답이 섞이지 않는다. UI busy 상태와 단일 실행 ref로 다음 페이지 중복 요청도 방지한다. 마지막 성공 조회와 최근 시도 시각을 별도로 표시한다.

새 경로를 로그인 복귀 allowlist에 추가했다. 처음 E2E에서 새 경로가 `/login`으로만 이동해 복귀 주소를 잃는 문제를 검출했으며, 두 역할·단일 거래 query 복귀 회귀를 추가하고 수정했다. 테스트 기준을 낮추지 않았다.
