# W11–W15 연속 실행 계획

**Goal:** 승인된 프로젝트 완성 로드맵의 W11–W15 구현과 재현 가능한 검증을 수행한다.
**Architecture:** 기존 Next.js 웹·MV3 확장·Supabase 계약을 유지하고 공통 접근성, 서버 집계, 동의 재검사, PWA 및 운영 검증을 additive하게 확장한다.
**Spec:** `docs/superpowers/specs/2026-10-02-project-completion-design.md`

## 제약
- 기존 미커밋 변경 보존. 커밋·push·PR 생성 없음.
- 학생/보호자 실계정과 Vercel 연결 없음. 이 조건이 필요한 검증은 미검증으로 기록.
- 금융 승인/환불 불확실 상태의 예약 포인트 유지. 자동 provider mutation 재실행 금지.
- 원본 URL·검색·본문을 보호자 응답/운영 로그에 추가하지 않음.

## 실행 순서
- [x] W11: 공통 모달 focus 관리, 모바일 공개 페이지, 로딩·오류 경계, 키보드/반응형 E2E 및 실제 harness 평가.
  대상: `apps/web/components/`, `apps/web/app/globals.css`, `apps/web/e2e/accessibility-responsive.spec.ts`.
- [x] W12: canonical 기록 집계에 원장 기준 포인트·디파짓 전환율 추가, 목표 계획 시간과 실제 집중 시간 분리, 시간대 집계의 측정 한계 표시.
  대상: `packages/contracts/src/index.ts`, `apps/web/features/history/`, additive SQL 및 pgTAP.
- [x] W13: AI 오류 분류, bounded provider timeout, 생성 완료 시 최신 동의/entitlement 재검사, 이전 가족 결과의 철회 노출 방지.
  대상: `supabase/functions/ai-writing/`, `_shared/`, AI UI 및 회귀 테스트.
- [x] W14: 사용자 확인 후 SW 업데이트, 공개 cache만 유지, 알림 권한·구독 해제·안전한 클릭과 서버 push 전달 경계 구현.
  대상: `apps/web/public/sw.js`, `components/pwa-register.tsx`, 알림 설정 및 push 서버.
- [x] W15: npm ci 기반 CI, DB/RLS, 공개/실계정 E2E gate 분리, read-only 운영 정체 탐지, 복구/배포 runbook.
  대상: `.github/workflows/`, `scripts/`, `docs/operations.md`, `docs/release-checklist.md`.

## 검증
각 동작에 단위/DB 회귀 테스트를 붙이고 마지막에 root/Web unit·lint·typecheck·production build·public secret scan·E2E·실제 MV3 smoke를 실행한다. 실제 계정/provider/지원 기기 검증을 mock 결과로 대체하지 않는다. 원격 배포는 배포 대상과 호환성 및 사용 가능한 인증을 확인한 후 가능한 범위만 실행한다.

## 실행 결과

체크는 구현과 명시된 로컬 검증 완료를 의미한다. 출시 완료는 아니다. [W11–W15 결과](2026-10-02-project-completion-w11-w15.md)에 테스트 범위, 원격 반영, 실계정·공급자·실기기 gate를 분리했다. 인증 화면의 전수 접근성 및 실제 공급자 여정은 미검증이다.
